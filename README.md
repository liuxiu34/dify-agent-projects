# Dify Agent 项目集（求职作品）

> 两个在 **Dify 云端**搭建、可导入可演示的 Chatflow Agent。本仓库存放可导入 DSL、回归证据与 Prompt 留痕。
> 所有 DSL 均已在 Dify 云端实跑验证（诊断 10/10、报销 v6.2 云端回归 12/12+1 记录边界）。

## 项目一：Java Web 异常自动诊断 Agent

输入异常日志 / Stack Trace，输出根因、证据、修复建议与验证步骤。

**结构（26 节点，Chatflow）**
```
输入预检 → 文档提取/合并 → 日志清洗脱敏 → Stack Trace 证据提取
 → 证据充分性判断 ──不足──→ 证据不足引导（只说明缺什么，不硬猜）
                 └─充分──→ 规则异常分类 → 知识检索(多路召回) → 上下文汇总
                             → 类型路由：SQL / NPE / AUTH / STARTUP 四路专项 LLM + 通用兜底 → 答复
```

**设计要点**
- 4 个 Python 代码节点承接确定性工作（预检/脱敏/证据提取/分类），LLM 只做根因分析；流程控制在条件分支
- 5 套专项 Prompt 分场景维护（SQL/NPE/AUTH/STARTUP/通用），可单独迭代
- 证据不足走独立分支，不强迫模型猜测

**验证**：Dify 云端回归 10 条真实异常日志 10/10 命中设计分支（见 `evidence/regression-诊断.md`）

## 项目二：企业报销预审助手（异常报销 Agent）

面向员工提交的报销单做合规预审：能过（L0 直通）/ 需轻量复核（L1）/ 复杂异常（L2 出建议、人工审批）。

**结构（24 节点，Chatflow）**
```
多轮会话状态机（证据补全 / 串单防护 / 发票 5 态非硬门槛 / 身份席别权限）
 → 规则引擎预审（Python 代码节点：住宿/餐补/交通/席别/发票规则确定性判定，L0 命中 0 Token）
 → L0 直通 / L1 轻量复核(LLM) / L2：槽位抽取 → 条款确定性匹配 → 复杂建议(LLM)
```
**设计要点**
- 确定性问题全部走代码节点（不调模型）：住宿超标 900>700、席别权限、发票金额冲突等
- 模型只出建议不做审批（HITL：L2 提示词内置决策黑名单）
- v6 里程碑：超标单结论直接写明「哪项指标超标 + 数值 vs 标准」，不要求员工补写超标原因文字
- 同会话多轮补全 + 串单防护（上一单完成后新消息一律按新单解析）

**验证**：云端回归 12 条场景通过 + 1 条扩展边界已记录（v6.2，见 `evidence/regression-报销-v6.2.md`）

## 关键指标

| 指标 | 值 |
|---|---|
| 云端交付 | 2 套 Chatflow（诊断 26 节点 + 报销 24 节点，可导入 DSL） |
| 回归验证 | 诊断 10/10 · 报销 12/12（v6.3 云端实测）+ 1 边界记录 |
| 评测集规模 | 500 条（正常 400 / 轻度异常 75 / 复杂异常 25） |
| 成本控制 | 正常单 LLM 调用率 0%（L0 规则直通）；Token 93.2 万 → 18.7 万（省 80%） |
| 发票/话术 | 发票 5 态矩阵（valid/suspicious/missing/conflict/declared_none），全链路无水单硬门槛 |

## 目录结构

```
dsl/                       可导入 Dify 的 DSL（导入 → 发布 → 即可用）
  ├─ java-web-diagnosis-agent.yml     诊断 Agent（26 节点）
  └─ expense-precheck-agent.yml       报销 Agent（24 节点，v6.3）
eval/                      评测体系（500 条评测集）
  ├─ README-评测集设计说明.md         分布依据 / 边界值 / 标注口径 / 统计 SQL
  ├─ eval-detail-500.json            500 条逐条明细（期望等级/实际结论/llm_calls/tokens）
  ├─ generator.py                    评测集生成器（分布可控 + 边界值 + 同义改写）
  └─ runner.py                       执行器（送真实链路落明细）
evidence/
  ├─ screenshots/          回归截图（画布 + 各分支实测）
  ├─ regression-诊断.md
  └─ regression-报销-v6.2.md
prompts/                   全部 LLM Prompt 留痕（诊断 5 套 + 报销 3 套）
```

## 运行方式

1. 打开 https://cloud.dify.ai → 应用 → 「导入 DSL」→ 选择 `dsl/*.yml`
2. 模型选用通义千问 `qwen3.7-flash`（诊断流需另配一个知识库：检索多路召回）
3. 画布点「发布」→ Web 界面或 API 即可对话

> 诊断流知识库说明：知识库检索为多路召回 + 按异常类型 metadata 过滤；本仓库只含工作流与 Prompt，
> 知识库文档为本地私有资料，未随仓库分发。
